## Resumen Ejecutivo

El backend Rust de OmniMon es **de alta calidad**. El codebase demuestra patrones defensivos maduros:
zero-allocation hot paths, RAII para recursos del OS, sanitización de inputs en boundaries IPC,
rate limiting por categoría de comando, y criptografía moderna (AES-256-GCM, Ed25519).

**95 tests pasan** (91 integración + 4 TUI). `cargo fmt --check` limpio. `cargo clippy` falla
únicamente por un issue del build system de Tauri (permisos de plugin faltantes), no por
warnings de código.

## 2. Bugs Encontrados

### CRÍTICOS

#### C-01: Pubkey vacío en updater de Tauri
- **Archivo:** `apps/desktop/src-tauri/tauri.conf.json:40`
- **Código:** `"pubkey": ""`
- **Impacto:** Las actualizaciones automáticas via CrabNebula CDN no verifican la firma Ed25519.
  Un atacante con capacidad MITM podría servir binarios maliciosos como actualizaciones.
- **Fix propuesto:**
```json
"pubkey": "<clave-pública-Ed25519-base64-de-tu-signing-key>"
```
- **Prioridad:** Bloquea release a producción. Debe resolverse antes del primer auto-update.

### ALTOS

#### A-01: Clave de encriptación hardcodeada en CLI SecurityScan
- **Archivo:** `crates/cli/src/main.rs:691`
- **Código:** `let key = [42u8; 32]; // Fixed key for demo`
- **Impacto:** Los reportes de seguridad encriptados generados por `omnimon security-scan` usan
  una clave predecible. Cualquiera con acceso al binario puede desencriptar los reportes.
- **Fix propuesto:**
```rust
// Generar clave desde el keyring del usuario o derivarla
let key = match keyring::Entry::new("omnimon_security", "scan_key")
    .and_then(|e| e.get_password())
{
    Ok(stored) => {
        let decoded = base64::engine::general_purpose::STANDARD
            .decode(&stored)
            .map_err(|e| format!("Invalid stored key: {e}"))?;
        let mut key = [0u8; 32];
        key.copy_from_slice(&decoded);
        key
    }
    Err(_) => {
        // Primera ejecución: generar y guardar
        let mut key = [0u8; 32];
        rand::thread_rng().fill(&mut key);
        let encoded = base64::engine::general_purpose::STANDARD.encode(&key);
        if let Ok(entry) = keyring::Entry::new("omnimon_security", "scan_key") {
            let _ = entry.set_password(&encoded);
        }
        key
    }
};
```
- **Contexto:** Marcado como "demo" — pero si el comando está disponible en el CLI de release,
  usuarios pueden asumir que sus reportes están seguros.

#### A-02: Fallback a almacenamiento plain-text para API keys
- **Archivo:** `apps/desktop/src-tauri/src/lib.rs:372-382`
- **Código:**
```rust
if macmon_core::ai::save_api_key(ai_provider, &trimmed_key).is_ok() {
    return Ok(());
}
// Fallback: persist in Tauri Store (JSON plano, sin encriptar)
store.set(ai_provider.keyring_service(), serde_json::Value::String(trimmed_key));
```
- **Impacto:** Si el keyring nativo del OS falla (ej: headless Linux sin Secret Service, contenedores),
  las API keys se guardan en un archivo JSON legible por cualquier proceso del usuario.
- **Fix propuesto:**
```rust
if macmon_core::ai::save_api_key(ai_provider, &trimmed_key).is_ok() {
    return Ok(());
}

// Fallback: encriptar antes de persistir en Tauri Store
tracing::warn!("Keyring unavailable — API key stored with app-level encryption");
let encrypted = macmon_core::crypto::encrypt_json(
    &serde_json::json!({"key": trimmed_key}),
    &app_encryption_key(),
).map_err(|e| format!("Encryption failed: {e}"))?;
store.set(
    ai_provider.keyring_service(),
    serde_json::Value::String(encrypted),
);
Ok(())
```

#### A-03: Cache de respuestas IA sin límite de tamaño
- **Archivo:** `crates/core/src/ai.rs:15-18`
- **Código:**
```rust
static AI_CACHE: OnceLock<RwLock<HashMap<u64, String>>> = OnceLock::new();
```
- **Impacto:** En sesiones largas con muchas consultas AI distintas, el HashMap crece sin límite.
  Cada respuesta es un String de hasta 4096 tokens (~16KB). Con 1000 consultas únicas = ~16MB sin
  posibilidad de liberación.
- **Fix propuesto:** Usar un LRU cache con capacidad máxima:
```rust
use std::collections::VecDeque;

const AI_CACHE_MAX: usize = 256;

struct BoundedCache {
    map: HashMap<u64, String>,
    order: VecDeque<u64>,
}

impl BoundedCache {
    fn insert(&mut self, key: u64, value: String) {
        if self.map.len() >= AI_CACHE_MAX {
            if let Some(old) = self.order.pop_front() {
                self.map.remove(&old);
            }
        }
        self.map.insert(key, value.clone());
        self.order.push_back(key);
    }
}
```

### MEDIOS

#### M-01: Clonación profunda en `get_cached_state()`
- **Archivo:** `crates/core/src/watcher.rs:333-339`
- **Código:**
```rust
pub fn get_cached_state() -> SystemState {
    let cache = state_handle();
    cache.read().map(|guard| guard.clone())
        .unwrap_or_else(|poisoned| poisoned.into_inner().clone())
}
```
- **Impacto:** Cada llamada IPC a `get_metrics()` (cada 2s) clona todo el `SystemState`, que
  incluye un `Vec<CachedProcessInfo>` con cientos de procesos (cada uno con Strings para
  name, exec_name, exe_path, bundle_id, group_name). En un sistema con 500 procesos, esto son
  ~50-100KB de allocaciones por tick.
- **Fix propuesto:** Retornar `Arc<SystemState>` en vez de clonar:
```rust
static CACHED_STATE: OnceLock<Arc<RwLock<Arc<SystemState>>>> = OnceLock::new();

pub fn get_cached_state() -> Arc<SystemState> {
    let cache = state_handle();
    cache.read().map(|guard| Arc::clone(&guard))
        .unwrap_or_else(|poisoned| Arc::clone(poisoned.into_inner()))
}
// En el tick del watcher:
*cache.write().unwrap() = Arc::new(new_state);
```
Esto reduce la clonación a un incremento atómico de refcount.

#### M-02: Clonación de `SuperProcess` en `telemetry_snapshot()`
- **Archivo:** `crates/core/src/telemetry.rs:48-53`
- **Código:**
```rust
for super_process in &super_processes {
    for pid in &super_process.pids {
        groups_by_pid.insert(*pid, super_process.clone());
    }
}
```
- **Impacto:** O(n*m) clonaciones donde n=super_procesos y m=pids por grupo. Para Chrome con
  20 procesos helper, esto clona 20 veces el mismo `SuperProcess`.
- **Fix propuesto:** Usar referencias o indices:
```rust
let groups_by_pid: HashMap<u32, usize> = super_processes.iter().enumerate()
    .flat_map(|(i, sp)| sp.pids.iter().map(move |&pid| (pid, i)))
    .collect();
// Luego: let grouped = &super_processes[*groups_by_pid.get(&entry.pid).unwrap()];
```

#### M-03: Patrón substring en automations
- **Archivo:** `apps/desktop/src-tauri/src/automations.rs:155-156`
- **Código:**
```rust
if proc.name.contains(&rule.process_pattern)
    || proc.exec_name.contains(&rule.process_pattern)
```
- **Impacto:** Falsos positivos. Una regla con pattern "chrome" matchea "Google Chrome",
  "Chrome Helper", "ChromeDriver", "chrome-sandbox", etc. Un usuario podría terminar procesos
  que no pretendía.
- **Fix propuesto:** Soportar regex o al menos coincidencia exacta de nombre:
```rust
// Opción 1: Exact match
if proc.name.eq_ignore_ascii_case(&rule.process_pattern)
    || proc.exec_name.eq_ignore_ascii_case(&rule.process_pattern)

// Opción 2: Regex (más flexible, requiere validación al crear regla)
use regex::Regex;
let re = Regex::new(&rule.process_pattern).map_err(...)?;
if re.is_match(&proc.name) || re.is_match(&proc.exec_name)
```

#### M-04: Separador invisible en parsing de tabs del browser
- **Archivo:** `crates/core/src/browser.rs:275`
- **Código:** `let mut parts = line.split('');` (U+001F, Unit Separator)
- **Impacto:** El carácter es invisible en editores y diffs. Si alguien modifica el script de
  AppleScript que genera este separador, puede introducir un bug silencioso.
- **Sugerencia:** Documentar el separador explícitamente:
```rust
const FIELD_SEP: char = '\x1F'; // ASCII Unit Separator (U+001F)
let mut parts = line.split(FIELD_SEP);
```

#### M-05: Poison recovery sin logging estructurado
- **Archivos:** Múltiples (`lib.rs`, `automations.rs`, `rate_limit.rs`, `plugins.rs`)
- **Patrón:**
```rust
.unwrap_or_else(|e| { eprintln!("..."); e.into_inner() })
```
- **Impacto:** Si un thread paniqueó y envenenó un lock, la recuperación ocurre silenciosamente
  (solo `eprintln`). En producción, un poisoned lock indica un crash previo — debería loggearse
  con `tracing::error!` para investigación.
- **Fix:** Reemplazar `eprintln!` con `tracing::error!` en todos los poison recoveries.

### BAJOS

#### B-01: `unwrap_or(0)` en `usize::try_from(read_len)` (WinDivert)
- **Archivo:** `crates/core/src/network.rs:807`
- **Código:** `let data = &buf[..usize::try_from(read_len).unwrap_or(0)];`
- **Impacto:** En la práctica, `read_len` es `u32` y `usize` es >= 32 bits en todas las
  plataformas soportadas (Windows 64-bit), así que la conversión nunca falla. El `unwrap_or(0)`
  es defensivo pero resulta en un slice vacío que simplemente se salta (`continue` en el parser).
  **No es un bug real**, pero podría cambiarse a `as usize` con un comentario.

#### B-02: `let _ = fs::remove_file(&dst)` ignora errores en rotación de audit trail
- **Archivo:** `crates/core/src/audit_trail.rs:98`
- **Impacto:** Best-effort cleanup. Si el archivo no se puede borrar (permisos), la rotación
  fallará en el `fs::rename` siguiente, que SÍ propaga el error. No es un issue real.

#### B-03: Sleep no-configurable de 300ms en kill graceful
- **Archivo:** `crates/core/src/killer.rs:244`
- **Código:** `std::thread::sleep(Duration::from_millis(300));`
- **Impacto:** Latencia fija entre SIGTERM y verificación. Es un compromiso razonable pero
  podría ser un parámetro configurable para procesos que necesitan más o menos tiempo de cleanup.

#### B-04: `System::new_all()` + `refresh_all()` en metrics fallback
- **Archivo:** `crates/core/src/metrics.rs:83-84`
- **Impacto:** Solo se ejecuta cuando el watcher no está corriendo (CLI cold-start, tests).
  En ese caso, `refresh_all()` es un full-scan del sistema — costoso pero infrecuente.
  Podría usar `refresh_processes()` selectivo.

## 4. Consistencia Cross-Platform

### ✅ Correcto

| Aspecto | Implementación |
|---------|----------------|
| Kill de procesos | `#[cfg(target_os)]` separado para Windows (TerminateProcess), Unix (libc::kill), con fallback genérico |
| Captura de red | macOS: libpcap, Windows: WinDivert, Linux: eBPF (aya) — cada uno con propio módulo |
| Keyring | `keyring 3` con features `apple-native`, `linux-native`, `windows-native` |
| Iconos de apps | Lógica separada para macOS (plist + sips), Linux (freedesktop), Windows (PowerShell + .ico) |
| FFI/unsafe | SAFETY comments en todos los bloques unsafe de `os_native.rs` |
| Paths | `PathBuf` consistente, sin hardcodeo de separadores `/` vs `\` |

### ⚠️ Observaciones

| Aspecto | Detalle |
|---------|---------|
| Network fallback | Si `pcap`/`aya` no están disponibles, el feature `network-capture` simplemente no se compila — no hay fallback graceful en runtime |
| WinDivert | Requiere driver de terceros instalado — no se incluye en el bundle MSI |
| eBPF (Linux) | Requiere CAP_BPF/CAP_NET_ADMIN — documentado pero sin detección runtime |
| macOS `lsof` | Invocación cada 2s via `Command::new("lsof")` — no FFI directo |

## 5. Patrones Tauri (IPC)

### ✅ Correcto — Thin-Command Pattern

Los command handlers en `lib.rs` delegan correctamente a `core`:
```
save_ai_config()    → core::ai::save_api_key()
kill_process()      → core::killer::kill_process_safe()
analyze_processes() → core::ai::analyze_processes()
get_metrics()       → core::watcher::get_cached_state()
```

### ✅ Serialización serde en boundaries IPC

- Todos los tipos retornados implementan `Serialize`
- Todos los parámetros recibidos implementan `Deserialize`
- No hay transmisión de tipos opacos (punteros, handles)

### ✅ Rate Limiting aplicado correctamente

| Comando | Perfil | Burst | Refill/s |
|---------|--------|-------|----------|
| `kill_process` | KILL | 10 | 5.0 |
| `analyze_processes` | AI | 10 | 2.0 |
| `ai_chat` | AI | 10 | 2.0 |
| `close_browser_tab` | BROWSER | 30 | 10.0 |
| `save_ai_config` | CONFIG | 5 | 2.0 |

### ✅ CSP correcto y restrictivo

```
default-src 'self';
style-src 'self';
connect-src 'self' https://openrouter.ai https://api.openai.com
  https://generativelanguage.googleapis.com https://api.anthropic.com;
script-src 'self';
form-action 'none';
frame-ancestors 'none'
```

**Solo** permite conexiones a los 4 providers de LLM conocidos. `frame-ancestors 'none'`
previene clickjacking. `form-action 'none'` previene exfiltración via forms.

### ⚠️ Falta `unsafe-eval` bloqueado explícitamente
`script-src 'self'` ya lo bloquea implícitamente. Correcto.

## 6. Seguridad — Resumen

### Fortalezas

1. **Criptografía moderna:** AES-256-GCM con nonces random, Ed25519 para firmas, SHA-256 para checksums
2. **Keyring nativo:** Credenciales en Keychain (macOS), Credential Manager (Windows), Secret Service (Linux)
3. **Sanitización exhaustiva:** `sanitize_tab_id()`, `sanitize_tab_url()`, `sanitize_file_stem()`, `check_prompt_injection()`
4. **Sandbox Lua:** 150ms timeout, 1MB memoria, 256KB script, 64 métricas max, hook de instrucciones
5. **Blocklist de procesos:** HashSet O(1) con procesos críticos del OS protegidos
6. **Catch unwind:** El watcher daemon no muere por panics de un tick individual
7. **Rate limiting:** Token bucket por categoría de comando IPC
8. **Zero-allocation watcher:** Buffers pre-allocados reutilizados entre ticks

### Debilidades

1. **Pubkey vacío en updater** (C-01) — CRÍTICO
2. **Clave hardcodeada en security-scan** (A-01) — ALTO
3. **Fallback plain-text para API keys** (A-02) — ALTO
4. **Cache IA sin límite** (A-03) — ALTO (memory leak potencial)
5. **Prompt injection blocklist es bypasseable** — la lista es corta y no cubre variaciones Unicode, encoding, etc. (riesgo moderado dado que el LLM no ejecuta código directamente)

## 7. Arquitectura — Puntos Positivos

1. **Separación clara core ↔ Tauri:** `core` es library pura sin dependencias de framework
2. **Watcher daemon:** Hilo background con double-buffering y zero-alloc design
3. **Workspace Cargo:** 4 crates con responsabilidades claras (core, cli, tui, desktop)
4. **Profile de release optimizado:** LTO, codegen-units=1, panic=abort, strip, opt-level=z

8. **Benchmarks:** Criterion para `get_cached_state()` performance
